# 부담도 모델 v2

> **10/25 유준 답장으로 바뀐 점 (정본은 유준 「백엔드 설계 명세서」).** 이 문서는 옮기기 전 참고용이다. 아래 3절과 5절, 완료 처리는 명세서를 따른다.
> - 날짜 칸 단계: 8주 대비 위치가 아니라 고정 기준선과 사람별 전체 수준 b로 정한 '예상 체감 7단계'. 체크인 답도 고정 구간의 가운데 D 값으로 바꿔 쓴다.
> - 개인 맞춤: 14개 전부가 아니라 4개(학업 계열, 일·팀플 계열, γ, b)만 맞춘다.
> - 완료한 마감의 준비 몫은 완료한 다음 날부터 뺀다.
> - 명세서에 넣기로 한 이 문서의 내용: 중요 × 1.3, 남은 준비 고치기(고친 날부터 다시 나누기), 노선도.

모든 계수는 가정이다. 팀이 확정하기 전까지 `src/burden/params.ts`에서만 조정한다.
이 문서는 팀 중간 발표 PPT 초안(10/25)과 강유준의 「백엔드 설계 명세서」(10/10)의 식을 따른다. 코드는 아직 v1(5단계)이고, 유준 저장소로 옮길 때 v2로 바꾼다.

## v1에서 바뀐 점 (10/25, 팀 PPT 반영)
- 표시는 7단계다(매우 편함 ~ 매우 힘듦). 저녁 체크인도 같은 7단계로 받는다.
- 식을 유준 명세서의 1차식 D(d)로 바꿨다. 가중치에 대해 1차식이어야 체크인으로 가중치 전체를 맞출 수 있다(5절).
- 준비 시간은 '만든 날'부터 마감 전날까지 날짜마다 똑같이 나눈다(PPT 7번: 10시간 → 5일에 2시간씩). 사용자가 남은 준비를 고치면 그날부터 다시 나눈다.
- 점수는 하루 적정량 C 대비가 아니라, 내 최근 8주 안의 위치(평소 대비 −100~+100)로 바꿔 단계를 정한다.
- 일정 종류를 시작 설정의 활동 목록과 같은 9개로 바꿨다(1절).
- 중요(☆) 배율 1.3은 그대로 둔다(10/8 팀 결정).
- 수업 비교 평가의 기본 방식은 '일반 캘린더'라서, v1 6절의 비교용 규칙 점수(`model=rule`)는 뺐다.
- 일정 블록 색의 압박도(pressure)는 PPT에 없어 뺐다.

## 목표
날짜마다 부담 점수 D(상한 없음), 평소 대비 값 s(−100~+100), 7단계 레벨을 내고 근거 목록을 함께 돌려준다.
월간 캘린더의 날짜 칸은 레벨로 색을 칠한다.

| 레벨 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|---|
| 이름 | 매우 편함 | 편함 | 약간 편함 | 보통 | 약간 힘듦 | 힘듦 | 매우 힘듦 |

## 입력
- 그날과 주변 날짜의 일정: 시작·종료, 종일 여부, 제목, 카테고리, 종류, 마감 여부, 준비 시간(과 남은 준비 수정 기록), 중요 여부, 완료 시각, 만든 날
- 사용자 설정: 쉬는 요일, 공휴일에 쉬는지, 일하는 날·쉬는 날의 기상·취침 시각, 활동별 부담(−2~+2)
- 가중치 θ: 시작 설정에서 만든 θ₀, 또는 체크인으로 맞춘 θ̂
- 최근 56일의 D 값(기준점 계산용)

## 1. 일정 종류 분류 (규칙 기반)

종류는 시작 설정에서 '활동별 부담'을 매기는 활동 목록과 같다.

| 종류(enum) | 키워드 예 | 마감일 때 기본 준비 시간 E₀ |
|---|---|---|
| class 수업 | 수업, 강의, 특강 | - |
| study 공부·과제 | 과제, 레포트, 리포트, 보고서, 제출, 공부, 스터디 | 2시간 |
| exam 시험·발표 | 시험, 중간고사, 중간, 기말, 퀴즈, 발표, PT, 프레젠테이션 | 시험 10시간(퀴즈 2시간), 발표 6시간 |
| team 팀플·회의 | 팀플, 회의, 미팅, 면담 | - |
| work 알바·일 | 알바, 근무, 출근 | - |
| social 모임·외출 | 약속, 밥, 저녁, 모임, 회식 | - |
| exercise 운동 | 운동, 헬스, 러닝, 수영 | - |
| rest 취미·휴식 | 휴식, 낮잠, 영화, 게임, 공연 | - |
| other 모름 | 일치 없음 | - |

E₀가 '-'인 종류에 마감(깃발)이 켜지면 준비 시간은 비워 두고 사용자가 정한다. 비어 있는 동안 P에서 뺀다.

규칙:
1. 제목 맨 앞의 `[카테고리]`를 떼고 남은 제목에서 찾는다. 남은 제목에서 아무 종류도 찾지 못하면 카테고리 이름에서 다시 찾는다. 예: `[지능HCI] 회의` → team, `[과제] DB 3장` → study.
2. 예외 사전을 먼저 본다. 예: '중간점검' → team ('중간'에 걸려 시험으로 분류되는 것을 막는다).
3. 여러 종류가 걸리면 우선순위로 하나를 고른다: exam > study > work > class > team > social > exercise > rest.
4. 마감 판정(isDeadline, 앱에서는 깃발): 제목에 '마감', '제출'이 있거나 종류가 exam이면 마감으로 본다. 키워드는 1번과 같은 순서(제목 → 카테고리 이름)로 찾는다.
5. 분류 확신도: 한 종류만 일치하면 high, 여러 종류가 걸리면 medium, 일치가 없으면 low.
6. 사용자가 종류, 준비 시간, 깃발을 고치면 그 일정에 고정한다(typeSource·deadlineSource·prepHoursSource = user).

## 2. 하루 점수 D(d)

```
D(d) = Σ m(i) · w_type(i) · dur_i(d)  +  α·B(d) + β·T(d) + γ·P(d) + ε·S(d) − δ·R(d)
```

시간 단위는 '시간'이다. θ = (w_class … w_other, α, β, γ, ε, δ)이고, θ₀는 아래 '시작값'이다.

| 항목 | 계산 규칙 | 시작값 |
|---|---|---|
| 일정 Σ m·w·dur | 일정마다 종류의 강도 w × 그날 안에 걸친 길이(30분 단위로 반올림). 강도는 시작 설정의 활동별 부담에서 정한다: +2 → 2, +1 → 1, 0 → 0.5, −1·−2(충전) → 0. other는 1. 종일 일정은 2시간으로 센다(가정). 제출처럼 길이가 없는 마감(종일 마감이거나 시작 = 종료)은 0(마감 부담은 P에서 센다). 완료한 일정도 시간이 있으면 센다 | 활동별 부담 기본값(아래) |
| m 중요 배율 | 중요(☆) 일정이고 w > 0이면 1.3, 아니면 1. P에도 같은 배율을 곱한다 | 1.3 (고정) |
| B 연속 일정 | 10분 미만 간격으로 이어진 일정 묶음마다 (묶음의 일정 수 − 1) | α = 1 |
| T 이른·늦은 시간 | 기상 전에 시작하거나 취침 뒤에 끝나는 일정의 수. 그날이 일하는 날인지 쉬는 날인지에 따라 기준 시각을 따로 쓴다 | β = 1 |
| P 마감 전 준비 몫 | 끝나지 않은 마감마다 준비 시간 E를 '시작일'부터 마감 전날까지 똑같이 나눈 그날 몫 × m. 시작일은 일정을 만든 날과 마감 14일 전 중 늦은 날이다. 마감이 만든 날과 같으면 그날에 모두 둔다 | γ = 1 (시간당) |
| S 쉬지 못한 날 | 마지막으로 쉰 날 이후 며칠째인지(쉰 날 다음 날 = 1, 쉰 날 당일 = 0), 최대 14. 쉰 날은 설정상 쉬는 날(쉬는 요일, 쉬는 공휴일)이면서 일정 점수 합(Σ m·w·dur)이 2 미만인 날이다 | ε = 0.5 |
| R 회복 | 충전 활동(활동별 부담이 −1·−2인 종류) 일정 가운데, 같은 날 뒤에 소모 일정이 이어지는 것의 시간 합. 최대 2시간 | δ = 1 (시간당) |

활동별 부담 기본값(가정, 시작 설정에서 사용자가 바꾼다): exam +2, class·study·team·work +1, social 0, exercise·rest −1. other는 따로 강도 1이다.

준비 몫의 세부 규칙:
- **만든 날 기준으로 나누는 이유.** '오늘'부터 나누면 날이 지날 때마다 지난 날짜의 값이 바뀐다. 만든 날 기준이면 기록이 고정되어 8주 기준점과 체크인 학습이 흔들리지 않는다.
- **남은 준비 고치기(PPT 7번 '이유 보기·수정').** 사용자가 날짜 r에 남은 준비를 E′로 고치면, r부터 마감 전날까지 E′를 다시 똑같이 나눈다. r 이전 날짜의 몫은 그대로 둔다.
- **완료.** 완료한 마감은 완료한 날(서울 기준)부터 몫이 0이다. 완료한 날 이전 날짜의 몫은 그대로 둔다.
- **준비 시간이 없는 마감**(prepHours = null)은 넣지 않는다.
- **공휴일.** 2026~2027년 공휴일 목록을 저장소에 JSON으로 둔다.

## 3. 평소 대비 값 s와 7단계

1. 최근 56일(어제까지)의 D 값을 모은다. 첫 로그인 때 가져온 구글 일정도 포함한다.
2. 이 값들의 0·20·40·60·80·100번째 백분위수를 기준점 k0~k5로 잡는다. 기록이 14일보다 적으면 기본 기준점 [0, 5, 8, 11, 16, 24](가정)를 쓴다.
3. D를 기준점 사이에서 선형 보간해 −100, −60, −20, 20, 60, 100에 맞추고, 범위 밖은 ±100으로 자른다. 그래서 s는 대략 '8주 중 백분위 × 2 − 100'이다. 빈 날이 많아 기준점이 겹치면 겹친 구간의 가운데 값을 준다.
4. 레벨 = s를 7칸으로 똑같이 나눈 칸 번호: `level = min(7, floor((s + 100) × 7 / 200) + 1)`.
5. 기준점은 사용자마다 하루 한 번, 그리고 체크인으로 가중치가 바뀔 때 다시 계산한다.

| 레벨 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|---|
| s 구간 | −100 ~ −71.4 | ~ −42.9 | ~ −14.3 | ~ 14.3 | ~ 42.9 | ~ 71.4 | ~ 100 |
| 기본 기준점에서 D | 3.6 미만 | 3.6 ~ 6.3 | 6.3 ~ 8.4 | 8.4 ~ 10.6 | 10.6 ~ 13.9 | 13.9 ~ 18.3 | 18.3 이상 |

## 4. 근거 (breakdown)
날짜를 누르면 보여 줄 근거 목록이다(PPT '부담 이유 보기'). 항목마다 키, 값(θ를 곱한 뒤), 한국어 한 줄 설명을 담는다.

```json
[
  { "key": "events",     "value": 1.5, "note": "수업 1시간, 팀 미팅 30분" },
  { "key": "prep",       "value": 2.0, "note": "11/16 지능HCI 발표 준비 몫 2시간" },
  { "key": "backToBack", "value": 0,   "note": "" },
  { "key": "offHours",   "value": 0,   "note": "" },
  { "key": "noRest",     "value": 0.5, "note": "마지막으로 쉰 날 이후 1일째" },
  { "key": "recovery",   "value": 0,   "note": "" }
]
```

key 값: events, prep, backToBack, offHours, noRest, recovery. recovery의 value는 뺀 값을 양수로 적는다.
중요 일정은 note에 '(중요 × 1.3)'을 붙인다. 예: `"지능HCI 발표 준비 몫 2.6시간 (중요 × 1.3)"`.

## 5. 개인 맞춤 (저녁 체크인)
체크인이 저장될 때마다 가중치 전체를 다시 맞춘다. 계산은 부담도 엔진처럼 DB 없는 순수 함수로 둔다.

1. **특징.** 체크인이 있는 날마다 D(d)를 이루는 값을 벡터 x_d로 모은다: 종류 9개별 (m × 길이) 합과 B, T, P, S, −R. 그러면 D(d; θ) = x_d · θ다. S의 '쉰 날' 판정만 지금 가중치로 정해 두고 푼다.
2. **답을 같은 척도로.** 체크인 단계 k(1~7)를 최근 8주 D 분포(지금 가중치로 계산)의 (100k − 50) / 7번째 백분위수로 바꿔 y_d로 쓴다. 1은 약 7번째, 4는 50번째, 7은 약 93번째다.
3. **풀기.** 닫힌 해로 바로 구한다. 음수가 된 값은 0으로 자른다.

   ```
   θ̂ = (XᵀX + λI)⁻¹ (Xᵀy + λθ₀)
   ```

4. **체크인이 적을 때.** λ가 θ̂를 θ₀ 근처에 붙잡는다. 같은 날 다시 답하면 덮어쓰고 다시 맞춘다. λ는 미정이다(가정 5).
5. **비교할 예측값.** 체크인과 비교하는 예측 레벨(predictedLevel)은 체크인을 받는 순간 그날 일정으로 계산한 레벨이다. 앱이 그날 처음 보여 준 레벨(firstShownLevel)도 따로 남긴다(PPT 12번 '낮 예상 부담 저장', 평가 분석용).
6. **말로 보여 주기.** θ̂가 θ₀와 많이 다른 항목 두 개까지를 "시험·발표를 처음 답보다 덜 힘들어함"처럼 문장으로 만든다(기준은 미정).
7. **시험용 사용자.** 수업 비교 평가의 시나리오 사용자는 체크인을 받지 않아 가중치가 고정된다.

## 6. 시작 설정 → θ₀
- 생활 유형: student, office, shift, freelance. 유형별 기본값은 팀 확정 후 정한다.
- 쉬는 요일, 공휴일에 쉬는지: S의 '쉰 날' 판정에 쓴다.
- 기상·취침 시각(일하는 날·쉬는 날): T에 쓰고, 자연어 입력에서 오전·오후를 고를 때 활동 시간으로도 쓴다.
- 활동별 부담(−2~+2): 2절 표의 강도로 바꿔 θ₀의 w가 된다.

## 7. 테스트 예시

### 점수 D
조건: θ = θ₀(2절 시작값), 기상 08:00·취침 23:00(모든 날), d는 일하는 날, 마지막으로 쉰 날 = d 하루 전(S = 1, ε·S = 0.5). 다른 조건이 있으면 그 줄에 적는다.

| # | 그날 일정 | 계산 | D |
|---|---|---|---|
| 1 | 수업 09:00~12:00 | 3 × 1 + 0.5 | 3.5 |
| 2 | 수업 09:00~10:30, 10:30~12:00 | 3 + B 1 + 0.5 | 4.5 |
| 3 | 알바 18:00~24:00 | 6 × 1 + T 1 + 0.5 | 7.5 |
| 4 | 일정 없음. 11/16 발표 마감(E 6 → 사용자가 10으로 고침)을 11/11에 만듦, d = 11/12 | P = 10 ÷ 5 = 2 | 2.5 |
| 5 | 4번과 같고 그 발표가 중요 | P = 2 × 1.3 = 2.6 | 3.1 |
| 6 | 4번 마감이 있고 d = 11/11, 수업 10:00~11:00, 팀 미팅 13:00~13:30 | 1 + 0.5 + P 2 + 0.5 | 4.0 |
| 7 | 6번에서 11/11에 남은 준비를 5시간으로 고침 | P = 5 ÷ 5 = 1, 11/10 이전은 그대로 | 3.0 |
| 8 | 7번 발표를 11/14에 완료, d = 11/14 | 11/14부터 P = 0 | 0.5 |
| 9 | 휴식 13:00~15:00, 수업 15:00~17:00 | 2 × 1 + B 1 + 0.5 − R 2 | 1.5 |
| 10 | 휴식 20:00~22:00 (그 뒤 일정 없음) | 휴식은 강도 0, 뒤에 소모 일정이 없어 R = 0 | 0.5 |
| 11 | 시험 13:00~15:00 (마감, 그날 시험) | 2 × 2 + 0.5 | 4.5 |
