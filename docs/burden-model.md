# 부담도 모델 v1

모든 계수는 가정이다. 팀이 확정하기 전까지 `src/burden/params.ts`에서만 조정한다.

## v0에서 바뀐 점 (10/8, 팀 스케치 반영)
- 종류 분류는 `[카테고리]`를 뗀 제목으로 하고, 제목에서 못 찾으면 카테고리 이름에서 찾는다.
- 마감(isDeadline)은 앱에서 깃발로 보이고, 사용자가 켜고 끌 수 있다.
- 완료한 마감은 완료한 날부터 '다가오는 마감 P'에서 뺀다. 준비 시간이 정해지지 않은 마감도 P에서 뺀다.
- 중요(☆) 일정은 w에 중요 배율 1.3을 곱한다(가정). 충전 일정에는 곱하지 않는다.
- 월간 캘린더의 날짜 칸은 레벨로 색을 칠한다.
- 규칙 점수의 `flag`를 `nearDeadline`으로 바꿨다(앱의 깃발과 헷갈리지 않게).
- 테스트 예시 7~11번과 종류 분류 테스트를 추가했다.

## 목표
날짜마다 점수(0~100 이상)와 5단계 레벨을 내고, 근거 목록을 함께 돌려준다.
보기는 3가지다: 전체(total), 힘든 일(load), 회복(recovery).
월간 캘린더의 날짜 칸은 이 레벨에 따라 색을 칠한다. 힘든 일·회복 보기에서는 같은 구간(2절의 레벨 구간)을 각 점수에 적용한다.

## 입력
- 그날과 주변 날짜의 일정: 시작·종료, 종일 여부, 제목, 카테고리, 종류, 마감 여부, 준비 시간, 중요 여부, 완료 시각
- 14일 이내의 마감
- 사용자 프로필: 활동 시간(activeStart~activeEnd, 기본 09:00~22:00), 쉬는 요일, 하루 적정량 C(시간, 기본 8), 종류별 가중치 w
- 개인 보정 배율 α (저녁 체크인에서 학습, 시작값 1)

## 1. 일정 종류 분류 (규칙 기반)

| 종류(enum) | 키워드 예 | 시간당 가중치 w | 마감일 때 준비 시간 E₀ |
|---|---|---|---|
| class 수업 | 수업, 강의, 특강 | 1.0 | - |
| exam 시험 | 시험, 중간고사, 중간, 기말, 퀴즈 | 2.0 | 10시간 (퀴즈 2시간) |
| assignment 과제 | 과제, 레포트, 보고서, 제출 | 1.2 | 2시간 |
| presentation 발표 | 발표, PT, 프레젠테이션 | 1.5 | 6시간 |
| meeting 팀플·회의 | 팀플, 회의, 미팅, 스터디, 면담 | 1.0 | - |
| parttime 알바 | 알바, 근무, 출근 | 1.4 | - |
| social 약속 | 약속, 밥, 저녁, 모임 | 0.6 | - |
| exercise 운동 | 운동, 헬스, 러닝, 수영 | -0.3 (충전) | - |
| rest 휴식·취미 | 휴식, 낮잠, 영화, 게임, 공연 | -0.6 (충전) | - |
| other 기타 | 일치 없음 | 1.0 | 사용자에게 묻는다 |

E₀가 '-'인 종류에 마감(깃발)이 켜지면 준비 시간을 사용자에게 묻는다.

규칙:
1. 제목 맨 앞의 `[카테고리]`를 떼고 남은 제목에서 찾는다. 남은 제목에서 아무 종류도 찾지 못하면 카테고리 이름에서 다시 찾는다. 예: `[지능HCI] 회의` → meeting, `[과제] DB 3장` → assignment.
2. 예외 사전을 먼저 본다. 예: '중간점검', '중간발표' → presentation ('중간'에 걸려 시험으로 분류되는 것을 막는다).
3. 여러 종류가 걸리면 우선순위로 하나를 고른다: exam > presentation > assignment > parttime > class > meeting > social > exercise > rest.
4. 마감 판정(isDeadline, 앱에서는 깃발): 제목에 '마감', '제출'이 있거나 종류가 exam이면 마감으로 본다. 키워드는 1번과 같은 순서(제목 → 카테고리 이름)로 찾는다.
5. 분류 확신도: 한 종류만 일치하면 high, 여러 종류가 걸리면 medium, 일치가 없으면 low.
6. 사용자가 종류, 준비 시간, 깃발을 고치면 그 일정에 고정한다(typeSource·deadlineSource = user).

## 2. 하루 점수

날짜 d에 대해 다음을 계산한다. 시간 단위는 '시간'이다.

- **중요 배율**: 중요(☆) 일정이고 w > 0이면 그 일정의 w에 m_imp = 1.3(가정)을 곱한다. 아래 E_load와 P의 w는 이 값을 쓴다. 충전 일정(w < 0)에는 곱하지 않는다.
- **일정 부하 E_load** = Σ w(e) × h(e), w > 0인 일정만. h(e)는 그날 안에 걸친 시간이다. 종일 일정은 h = 2로 둔다(가정). 단 제출 마감처럼 길이가 없는 마감 일정(종일이거나 시작 = 종료)은 h = 0이다(마감 부담은 P에서 센다). 시험처럼 시간이 있는 일정은 그 시간만큼 E_load에도 더한다. 완료한 일정도 시간이 있으면 그대로 센다(실제로 한 일이므로).
- **연속 일정 B** = 0.5 × (간격 15분 이하로 이어진 일정 쌍의 수)
- **이른 시작·늦은 종료 T** = 0.5 × (activeStart 이전 일정 시간 + activeEnd 이후 일정 시간)
- **다가오는 마감 P** = Σ w(i) × E(i) / days_left(i), 마감일이 d 이후 1~14일 안에 있는 마감 i만. days_left = max(1, 마감 날짜 − d). 오늘부터 시작한다고 할 때 하루에 해야 할 몫이므로, 마감이 가까워질수록 커진다.
  - 완료한 마감은 완료한 날(서울 기준)부터 뺀다. 완료한 날 이전 날짜의 점수는 그대로 둔다.
  - 준비 시간이 정해지지 않은 마감(prepHours = null)은 넣지 않는다.
- **쉬지 못한 날수 F** = 1 + 0.05 × min(streak, 6). streak는 d 직전까지 레벨 3 이상이 이어진 날의 수이고, 레벨 2 이하인 날에서 끊긴다. 날짜 순서대로 계산한다.
- **회복 R** = Σ |w(e)| × h(e), w < 0인 일정만. 여기에 쉬는 요일이고 E_load < 1이면 1.0을 더한다.

```
load_raw  = (E_load + B + T + P) × F
total_raw = max(0, load_raw − R)

score_load     = α × 100 × load_raw  / C
score_recovery =     100 × R         / C
score_total    = α × 100 × total_raw / C
```

레벨(score_total 기준, 체크인 5단계와 같은 축): [0,20) → 1, [20,40) → 2, [40,60) → 3, [60,80) → 4, 80 이상 → 5.

마감 일정에는 일정 블록 색을 위한 압박도도 함께 돌려준다: pressure = E / H_free. H_free는 지금부터 마감까지 활동 시간 중 일정이 없는 시간이다. 완료한 마감은 pressure를 돌려주지 않는다(null).

## 3. 근거 (breakdown)
날짜를 누르면 보여 줄 근거 목록이다. 항목마다 종류, 한국어 한 줄 설명, 점수를 담는다.

```json
[
  { "kind": "event",       "label": "시험 2시간 × 2.0",                          "points": 50,   "refId": "evt_123" },
  { "kind": "consecutive", "label": "쉬는 틈 없이 이어진 일정 1쌍",                 "points": 6.3 },
  { "kind": "early_late",  "label": "22시 이후 일정 1시간",                         "points": 6.3 },
  { "kind": "deadline",    "label": "DB 과제 마감 D-2: 준비 2시간 ÷ 2일 × 1.2",      "points": 15,   "refId": "evt_456" },
  { "kind": "fatigue",     "label": "3일 연속 바쁜 날 × 1.15",                      "points": 8.4 },
  { "kind": "recovery",    "label": "휴식·취미 2시간",                               "points": -15 },
  { "kind": "calibration", "label": "내 체감 보정 × 1.2",                            "points": 9.8 }
]
```

kind 값: event, consecutive, early_late, deadline, fatigue, recovery, calibration.
중요 일정은 label 끝에 '× 중요 1.3'을 붙인다. 예: `"발표 1시간 × 1.5 × 중요 1.3"`.

## 4. 개인 보정 (저녁 체크인)
- 체크인은 하루 한 번, 1~5단계. 체감 점수 s_obs = {1: 10, 2: 30, 3: 50, 4: 70, 5: 90}.
- 예측 점수 s_pred = α를 곱하기 전의 total 점수.
- 기록마다 비율 r = s_obs / max(s_pred, 10).
- α = (k₀ × 1 + Σ r) / (k₀ + n). k₀ = 7은 시작값의 무게, n은 기록 수다. α는 [0.5, 2.0]으로 자른다. 최근 28일 기록만 쓴다(가정).
- 기록이 적으면 α는 1(시작값) 근처에 머물고, 쌓이면 실제 체감 쪽으로 움직인다.
- 시간이 되면(다음 모델 버전): 종류별 가중치를 시작값 쪽으로 당기는 릿지 회귀로 학습한다.

## 5. 시작 설정 → 초기값
- 하루 적정량 C: 사용자가 입력한다(기본 8시간). 생활 유형별 기본값은 팀 확정 후 정한다.
- 활동 시간: activeStart / activeEnd (기본 09:00 / 22:00)
- 쉬는 요일: 회복 보너스와 streak 계산에 쓴다.
- 활동별 소모·충전: 위 표의 w를 사용자가 조정한 값이 시작값이다.

## 6. User Study B 조건용 규칙 점수
`GET /v1/burden/days?model=rule`은 비교 실험의 '규칙 색' 조건을 위한 점수를 돌려준다.
- 레벨 = clamp(그날 일정 개수, 1, 5)
- 마감 D-2 이내인 일정은 `nearDeadline`으로 표시한다.

## 7. 테스트 예시

### 점수
조건: C = 8, α = 1, activeStart 09:00, activeEnd 22:00, 이전 날 streak = 0 (6번 제외).

| # | 그날 일정 | 계산 | score_total | 레벨 |
|---|---|---|---|---|
| 1 | 수업 09:00~12:00 | E_load = 3 | 37.5 | 2 |
| 2 | 수업 09:00~10:30, 10:30~12:00 | E_load = 3, B = 0.5 | 43.75 | 3 |
| 3 | 알바 18:00~23:00 | E_load = 5 × 1.4 = 7, T = 0.5 × 1 | 93.75 | 5 |
| 4 | 일정 없음, 시험 마감 D-5 (E₀ 10, w 2.0) | P = 2.0 × 10 / 5 = 4 | 50 | 3 |
| 5 | 4번 + 휴식·취미 2시간 | R = 0.6 × 2 = 1.2, total = 4 − 1.2 | 35 | 2 |
| 6 | 4번과 같고 직전 3일 연속 레벨 3 이상 | F = 1.15, 4 × 1.15 = 4.6 | 57.5 | 3 |
| 7 | 일정 없음, 종일 마감 `[지능HCI] 발표 자료 제출` D-1 (presentation, E₀ 6, w 1.5) | P = 1.5 × 6 / 1 = 9 | 112.5 | 5 |
| 8 | 7번과 같고 그 마감을 d에 완료 | P = 0 | 0 | 1 |
| 9 | 1번과 같고 그 수업이 중요 | E_load = 3 × 1.0 × 1.3 = 3.9 | 48.75 | 3 |
| 10 | 4번과 같고 그 시험이 중요 | P = 2.0 × 1.3 × 10 / 5 = 5.2 | 65 | 4 |
| 11 | 5번과 같고 휴식·취미가 중요 | 충전 일정에는 곱하지 않음, 5번과 같음 | 35 | 2 |

개인 보정 예시: 7일 동안 매일 s_pred = 50, 체크인 4단계(s_obs = 70)이면 r = 1.4, α = (7 + 9.8) / 14 = 1.2.
